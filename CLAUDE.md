## Architecture

- Pure static HTML, CSS, and vanilla JavaScript.
- No build step and no package manager.
- `staff-tool.html` is the launcher; each tool is its own page reached via `openURL(...)`. The `screen-*` / `showScreen()` machinery still in `staff-tool.html` is dead code — do not extend it.
- Price Battle opens as a same-site GitHub Pages HTML page, not through raw Gist fetch/document.write.
- Two external dependencies:
  - `QRCode.js` from cdnjs (loaded by several pages, not just Belkin).
  - Apple's product image CDN `store.storeimages.cdn-apple.com`, used only by `case-simulator.html`. No auth, no version token, `access-control-allow-origin: *`, but `cache-control: max-age=121` — so that page needs a live connection and is not usable offline.
- Public pages include `noindex` meta tags to discourage search indexing. This is not access control.
- The public `One-Shortcuts/One-Shortcuts` repo is generated by the deploy script and should contain only deployable HTML files.

## Case Match

Shows Apple's real product photos of a given case on each iPhone body colour.

The user-facing name is **Case Match** (title, header, launcher entry). The file is
still `case-simulator.html` — the name was changed after the page shipped and the
filename was left alone to keep the deploy list and the launcher link stable.

Image URL is constructed, not stored:
`https://store.storeimages.cdn-apple.com/1/as-images.apple.com/is/{CODE}?wid=1000&hei=1000&fmt=jpeg&qlt=90`
where `{BASE}` is the part number minus its 2-char region suffix (`MHVM4FE/A` → `MHVM4`),
and `{CODE}` is one of:

| code | what it is |
|---|---|
| `{BASE}_AV{n}` | the numbered shot series |
| `{BASE}` (bare, no suffix) | **a real 5th shot, not a duplicate** — see below |
| `{BASE}_SW_COLOR` | the case colour swatch (64×64); also a cheap SKU existence oracle |

**The bare `{BASE}` code is the shot the `_AV` series omits.** This was the finding
that closed the catalogue: for these 48 SKUs the `_AV` run covers all but one of the
model's phone colours, and the bare code is that missing one. In `CASES` it is stored
as `av: 0`, and `shotURL()` emits no `_AV` suffix for 0.

Be precise about how strongly that is established, because it reads stronger than it is:
- *Verified mechanically:* every one of the 48 `_AV` runs omits **exactly one** colour,
  and all 164 URLs return 200.
- *Verified only visually:* which colour each bare shot actually shows. Deriving it
  "from the omission" is **not** independent evidence — it assumes the very rule being
  tested. The colour identities rest on the plateau read alone.
- *Known counter-example to the rule:* Beats was excluded partly because its bare
  case-back shot is sometimes not even the right colour. So the bare code is **not**
  universally the omitted-colour shot; it holds across these 48 and must be re-read
  visually for any SKU added later.

**The single rule that matters:** the `_AV{n}` index encodes *which iPhone body
colour the case is photographed on*, and it varies **per SKU** — Apple picks a
phone colour that flatters each case colour. On iPhone 17, `AV3` is Mist Blue for
some cases and White for others; `AV1` is Lavender for most but White for MHVT4.
It also differs per model (iPhone 17 `AV1` = Lavender, iPhone 17 Pro `AV1` =
Cosmic Orange). Some slots are not colour shots at all (screen-on, or a generic
dark detail shot that is not even the selected colour).

Therefore the `shots` map in `CASES` is **hand-verified data and must never be
computed**. A wrong entry does not throw — it silently shows a customer the wrong
thing. `VERIFIED` records when it was last checked and is surfaced in the footer.

Coverage: **48 SKUs, 164 combinations, 100% real Apple photography — no
compositing, no recolouring, no gaps.** Across iPhone 17 / 17 Pro / 17 Pro Max /
Air / 17e, in Silicone, TechWoven, Clear, Bumper and Case-with-MagSafe. Every
image URL was re-probed and returns 200.

**Beats and Tech21 are deliberately excluded** — Apple publishes no
case-on-phone-colour photography for them (their image slots are lifestyle scenes,
front screen-on shots, and a bare case back that is sometimes not even the right
colour).

### History: the removed simulation engine

An earlier version filled 42 missing combinations by compositing in the browser
(alpha `MASKS` per `model|family`, phone region transplanted from a donor case),
badged them "Simulated", and left 6 as honest gaps. **All of that was deleted**
once the bare-`{BASE}` shot was found, because it turned out no combination was
actually missing. The file went 134KB → 38KB.

Do not reintroduce it. If a future model genuinely lacks a shot, prefer showing
the honest gap: `renderStage` already renders "No photo published" for any colour
absent from `shots`, kept visually distinct from a network/404 failure.

All image loads still use `crossOrigin='anonymous'`, **including plain display
images**. Nothing draws to a canvas today, but with `max-age=121` a cached
non-CORS response would taint one later, despite `ACAO: *` — the attribute is
cheap and removing it would fail silently much later.

Ruled out as image sources (do not re-investigate):
- Higher `_AV` indices — probed AV1–AV16, nothing beyond what is mapped.
- Other Apple regions — US `MGF24LL` / `MGFT4LL` / `MGFW4LL` share the same 5-char
  base as the TH SKUs, so the CDN serves identical images.
- Apple's bare-phone `iphone-*-finish-*` images — a two-phone composition at
  completely different framing, not usable alongside the case shots.

To refresh the catalogue, re-derive from Apple's sitemap
(`https://www.apple.com/th/shop/sitemaps/product.xml`) and re-verify the shot
mapping visually.

## Behavioral expectations

- `staff-tool.html` is the launcher and main tool container.
- Internal launcher buttons must not fetch raw Gist HTML and replace the document.
- The page should work when opened from GitHub Pages or locally from the repo folder.
- Keep the content self-contained and avoid external app dependencies unless already required.
